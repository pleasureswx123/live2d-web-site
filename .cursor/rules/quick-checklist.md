# 技术决策快速检查清单

## 🚨 紧急停止信号
如果遇到以下情况，立即停止并重新思考：
- 基于"直觉"或"经验"做决策
- 没有查阅官方文档
- 没有创建测试验证假设
- 解决方案过于复杂
- 与项目架构不一致

## ✅ 技术决策前必查清单

### 1. 问题分析
- [ ] 我是否明确了问题的技术栈？
- [ ] 我是否查阅了官方文档？
- [ ] 我是否了解了问题的根本原因？
- [ ] 我是否考虑了问题的范围？

### 2. 假设验证
- [ ] 我的假设基于什么？
- [ ] 我是否创建了测试用例验证假设？
- [ ] 我是否考虑了反例？
- [ ] 我是否避免了认知偏差？

### 3. 解决方案评估
- [ ] 解决方案是否与项目架构一致？
- [ ] 是否避免了过度工程？
- [ ] 是否考虑了长期维护成本？
- [ ] 是否保持了代码简洁性？

## ✅ 代码编写前必查清单

### 1. 架构一致性
- [ ] 是否遵循项目技术栈？
- [ ] 是否复用了现有组件？
- [ ] 是否遵循项目设计模式？
- [ ] 是否保持代码风格一致？

### 2. 代码质量
- [ ] 是否避免了重复代码？
- [ ] 是否添加了错误处理？
- [ ] 是否考虑了边界情况？
- [ ] 是否添加了必要注释？

### 3. 性能与安全
- [ ] 是否避免了性能问题？
- [ ] 是否考虑了安全性？
- [ ] 是否正确处理了异步操作？
- [ ] 是否避免了内存泄漏？

## 🧪 测试验证模板

### 状态管理测试
```javascript
// 遇到状态管理问题时，先创建这个测试
const testStore = create((set, get) => ({
  value: null,
  setValue: (v) => {
    console.log('设置前:', get().value)
    set({ value: v })
    console.log('设置后:', get().value)
    console.log('立即获取:', get().value)
  }
}))
```

### API 调用测试
```javascript
// 遇到 API 问题时，先创建这个测试
const testAPI = async () => {
  try {
    const response = await fetch('/api/test')
    const data = await response.json()
    console.log('API 响应:', data)
  } catch (error) {
    console.error('API 错误:', error)
  }
}
```

## 🚫 必须拒绝的代码

- 基于未验证假设的代码
- 与项目架构不一致的代码
- 过度复杂的解决方案
- 缺乏测试的代码
- 违反项目规范的代码
- 性能有明显问题的代码
- 缺乏错误处理的代码

## 🔧 必须改进的代码

- 缺乏文档的代码
- 命名不清晰的代码
- 函数过长的代码
- 嵌套过深的代码
- 重复的代码
- 硬编码的代码

## 🎯 核心原则

**验证 > 假设，文档 > 经验，测试 > 直觉**

记住：**好的代码是设计出来的，不是调试出来的。好的架构是思考出来的，不是堆砌出来的。**
